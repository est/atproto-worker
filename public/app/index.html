        How this works and what it trusts
        

          

            The Worker is a channel, not a signer. It stores and serves
            the repo, verifies the P-256 signature on each append event, and relays the
            result. It never receives the private key.
          

          

            The key is owner-side: it is encrypted with your passphrase
            and kept in this browser's localStorage. Signing happens with WebCrypto in
            this tab. The private key is not placed in a URL, a log, or a request body.
          

          

            The page itself is a trust boundary. When the Worker hosts it, a compromised
            Worker could serve modified JavaScript and use your unlocked key as a signing
            oracle. For stronger security, host these same files on an independent static
            origin (or run them locally) and point them at the Worker URL. Use the
            Backup button to keep an encrypted copy, and lock the page when done.
          

          

            A write carries a client-built MST/commit/CAR. On 409 RepoConflict
            the page discards the local commit and refuses to silently re-sign; refresh and
            retry from the new head.
