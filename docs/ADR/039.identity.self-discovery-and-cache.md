## Context

多账号（ADR-038）落地后暴露出配置残留：发布账号公钥存在 `public/accounts.json` 注册表、主账号公钥依赖 `OWNER_PUBLIC_KEY` 环境变量/secret。用户提出完全自发现模型：

1. journal.ndjson 每行已带 `did` → `did:web:<handle>` 即账号；
2. 解析 handle → well-known URL（`https://<handle>/.well-known/did.json`）；
3. 访问 well-known 取公钥 —— **主账号（回环自己域名）边缘层禁止，catch 后读 ASSETS 静态文件**；
4. 其余配置同样自发现，**无需单独维护注册表**。

源码确认：indigo `ResolveHandle`（handle.go:175-238）DNS TXT 失败后**回退 HTTP well-known**（`GET https://<handle>/.well-known/atproto-did`，body=did）—— 账号 handle 解析也不需要 DNS。主账号的 `/.well-known/atproto-did` 也变为静态文件，主 handle 同样走 well-known 解析路径。

同时调研 CF Workers Cache（workers/cache）：`[cache] enabled` 后**缓存命中时 Worker 完全不运行（CPU 不计费）**，带 tiered cache 与 request collapsing —— 确定性只读端点缓存后，重复读取不再执行每请求的 journal 加载与校验（ADR-027 的 CPU 成本在缓存命中时归零）。

## Decision

### 1. 身份自发现（零配置）

- **无注册表、无环境变量**：hosted 账号 = journal 去重 did（`distinctDids()`）；公钥一律 well-known 自发现；
- **主账号**：`seal.js init` 生成静态 `public/.well-known/did.json`（含公钥）与 `atproto-did`，随 Worker 部署；worker 服务这两个文件（ASSETS），describeServer/describeRepo 的 didDoc 从静态文件/well-known 自发现 —— `OWNER_PUBLIC_KEY` 环境变量与 secret 删除；
- **发布账号**：公钥从 `https://<handle>/.well-known/did.json` 获取（`src/identity.js`），**Cache API**（caches.default）缓存 5 分钟（外部源非本 Worker 响应，Workers Cache 管不到）；
- **getBlob** 按 handle 派生命名空间 `uploads/<handle>/`（主账号保持 `uploads/` 根，向后兼容）。

### 2. Workers Cache 降成本

- `wrangler.toml` 加 `[cache] enabled = true`；
- 确定性只读端点加 `Cache-Control: public, max-age=…`：did.json / atproto-did（300s）、describeServer（60s）、getRepoStatus / getLatestCommit / listRepos（30s）、getBlob（86400s，内容按 cid 不可变）—— 缓存命中不跑 Worker；
- **不缓存**：/refresh（触发广播）、checklist 页（动态状态）、getRecord / listRecords / getRepo（数据随部署变化，新鲜度优先）—— 新帖发布后 ≤TTL 生效，relay/appview 有自身延迟，可接受；
- 代价：启用缓存后静态资产请求从"不计费"变"计标准请求费"（文档明确）—— 个人规模可忽略。

## Consequences

优点：

- **配置归零**：CF 侧无 secret、无 KV、无注册表；journal 是唯一事实来源，公钥全部 well-known 自发现；
- **CPU 成本下降**：确定性端点缓存命中不执行 Worker —— 每请求 journal 全量校验（ADR-027）在重复读取时消失，无需部署感知缓存；
- 主账号 handle 也获得 well-known 解析路径（atproto-did 静态文件），不依赖索引学习；
- 发布账号接入 = 持有者放两个静态文件，零 DNS。

缺点：

- 发布账号公钥依赖其域名的 well-known 可达性（fetch 失败则 describeRepo 报错；缓存 5 分钟缓解）；
- 数据端点（getRecord/getRepo）不缓存，新帖部署后 ≤30-300s 才在状态类响应中可见（relay 走 firehose 不受影响）；
- Workers Cache 使静态资产请求计费（个人规模可忽略）；
- 主账号 did.json 变静态文件：换钥需重新 `init` 并部署（与之前改 wrangler.toml 再部署等价）。
