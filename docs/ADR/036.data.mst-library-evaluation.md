## Context

代码评估（2026-08-16）发现 Merkle Search Tree 是本项目最大的一块自研轮子（`cli/mst.js`，约 547 行），质疑是否值得保留。按"不自造轮子 + 库不带大依赖树"的原则调研现成库：

| 候选 | 依赖树 | 判定 |
|---|---|---|
| `@atproto/repo`（官方，含 MST） | 8 直接依赖 + 传递树 | ❌ 违反"不带一大坨依赖" |
| `@atcute/mst` | `@atcute/cbor`→`@atcute/cid`→`@atcute/multibase`/`@atcute/uint8array`，共 5 个小包，无第三方 | ✅ 达标 |

为裁决"换不换"，新增**对拍测试**（`tests/mst-atcute.test.js`，`@atcute/mst` 仅作 devDependency）：把官方 6 个 commit-proof fixtures 的同一组 keys 分别喂给自研 MST 与 @atcute/mst，比较 MST root。

**对拍结果：6/6 全部 PASS，两边产出的 root 与官方 `rootBeforeCommit` 逐字节一致**（含空树 CID、getKeyHeight == 我们的 leadingZerosOnHash）。两者算法字节级等价，自研实现的正确性再次被独立实现交叉验证。

## Decision

**保留自研 `cli/mst.js`，暂不换 @atcute/mst。** 理由：

1. **字节级一致 = 换库无正确性收益**：两者产出完全相同，不存在"修复潜在 bug"的动机；
2. **稳定优先**（本阶段目标：写路径（ADR-035）之前把"文本只读广播"核心做稳）：自研 MST 已验证、零依赖、被 e2e/mst/fixtures 三套测试覆盖；换库是对稳定代码的扰动；
3. **供应链约束**：自研 = 0 运行时依赖；@atcute/mst = 5 个小包。收益为零时，更少依赖 = 更少供应链风险（用户明确要求）；
4. **集成成本被低估**：对拍测试的 ~15 行适配只是冰山一角 —— 实际换库需把 RepoManager（cli/repo.js）从 OO 模型（`add()` 返回新 MST、`getUnstoredBlocks`、`load(blockstore, cid)` 从 blocks 重建）改成 @atcute 的函数式模型（`putRecord` 返回 root、独立 blockstore、CidLink 转换），且语义有差异（重复 add 静默 no-op vs 我们抛错）；
5. **对拍测试永久保留**：既持续守护自研实现的正确性，也证明换库路径随时可行。

**再评估触发条件**：启动写路径工程（ADR-035 的完整 PDS）时重新评估 —— 届时需要服务端构建/操作 MST，@atcute 生态（mst/cbor/cid）是更完整的基座，换库价值随之上升。

## Consequences

优点：

- 核心零新依赖，供应链面最小（用户硬约束）；
- 自研 MST 获得独立实现交叉验证（对拍测试常驻），正确性证据更充分；
- 换库路径已探明（API 差异、适配点、语义差异全部记录），未来触发再评估时成本已知。

缺点：

- 547 行自研代码继续维护（对拍测试证明其与官方实现等价，维护风险低）；
- @atcute/mst 停留在 devDependency（测试用），不进入运行时 —— 若将来要换，需从 dev 转运行时依赖。
