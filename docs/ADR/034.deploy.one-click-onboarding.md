## Context

目标：让"对 atproto 和 Cloudflare 一窍不通"的人也能把项目跑通 —— 点一个按钮，然后照着首页提示一步步完成（当前设定：只能发文本、单向广播到联邦、互动只打日志）。

原 ADR-017（draft）假设一键部署依赖 R2（ADR-012）与 Web UI（ADR-013），两者均未落地且已被架构演进淘汰。实际落地路径比草案简单得多，因为：

- **身份可自动派生**：fetch 处理中 `did = env.OWNER_DID || did:web:${url.host}`、`handle = env.OWNER_HANDLE || url.host` 的 fallback 早已存在（scheduled 路径缺失，需补）。did:web 身份 = 域名本身，部署按钮分配的子域名即可直接作为身份，**无需任何身份配置**。
- **wrangler.toml 此前硬编码了现网身份**（yiesty 的 DID/HANDLE/公钥）—— 公开部署按钮若直接部署该文件，任何部署者都会拿到 yiesty 的身份（错误且不安全）。必须移除。
- **OWNER_PUBLIC_KEY 不可派生**：它是加密身份（did.json 的 verificationMethod，relay 验签依据，ADR-030）。这是整个流程中**唯一必须手动**的一步。
- **首页已是 checklist 页**（`/` 的 renderChecklistPage）—— 升级为向导即可，无需新增入口。

## Decision

### 1. 一键部署（Deploy with Workers 按钮）

- README 增加标准按钮：`https://deploy.workers.cloudflare.com/?url=https://github.com/est/atproto-worker`；
- **wrangler.toml 移除全部身份变量**（OWNER_DID/OWNER_HANDLE/OWNER_PUBLIC_KEY/JOURNAL_URL），改为注释模板 —— 部署按钮产物对任何人都是中立配置，不会误用他人身份；
- Worker 自动推导：fetch 路径沿用现有 fallback；**scheduled 路径补上**（以 OWNER_HANDLE 为锚推导 did:web，因为 scheduled 无请求 host）；
- cron 的 refresh 门控从 `if (env.JOURNAL_URL)` 放宽为 `if (env.ASSETS || env.JOURNAL_URL)`（ASSETS 是默认数据源，不应依赖可选 URL）；
- notifyRelay 改用推导后的 handle（从 /refresh 传入），不再读裸 env。

### 2. 首页部署向导（`src/setup.js` 重写）

- 分三阶段展示：① **一键部署（自动就绪）**：firehose、journal 加载、DID/句柄自动识别（显示推导后的实际值）；② **身份配置（唯一手动）**：OWNER_PUBLIC_KEY —— 给出逐步指引（clone + npm install + `seal.js init` → 复制 publicKeyMultibase → Dashboard 加变量 → 部署）；③ **可选**：JOURNAL_URL（外部托管才需要，默认静态资产）。
- **「下一步」卡片**：根据第一个未完成项动态给出人话版操作步骤（含可复制命令）；全部完成后变为"发布第一条帖子"指引（post → cp → git push → curl /refresh）。
- **联邦实测按钮**：页面 JS 直接探测 `resolveHandle` / `getProfile` / relay `getRepoStatus`（CORS 可用则显示状态；不可用给 curl 兜底命令）。

### 3. 现网迁移

移除 wrangler.toml 身份变量后，现网部署（yiesty）通过 `wrangler deploy --var OWNER_PUBLIC_KEY:zQ3sh...` 显式传入公钥保持联邦不中断；DID/句柄自动推导值与现状完全一致（`did:web:atproto-worker.yiesty.workers.dev`）。

## Consequences

优点：

- 上手门槛从"8 步手工部署"降到"点按钮 + 唯一一步公钥配置"（本地仍需要 Node 跑一次 `seal.js init` —— 签名必须在本地，ADR-005）；
- 部署产物中立安全：不会误部署他人身份；身份错误配置（缺公钥）在向导里被显式拦截并指引修复；
- 首页即教程，向导与代码状态联动，不会出现"文档说完了但不知道做到哪一步"。

缺点：

- **发帖仍依赖本地 Node**：这是当前"本地签名 + 静态发布"架构的硬约束（ADR-014/ADR-005）；向导只能把命令做成复制粘贴，无法完全免终端 —— 已作为已知边界记录；
- 一键部署的默认 worker 域名身份（`did:web:<子域名>`）可被 relay 收录，但自定义域名/`_atproto` TXT 等高级需求仍需手动（超出当前设定）；
- `wrangler.toml` 失去"开箱即用身份"，对愿意直接编辑 toml 的开发者多一步 —— 向导已覆盖。
