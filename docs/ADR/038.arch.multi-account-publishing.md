## Context

目标：一个单向图文发布 PDS 托管多个"发布类账号"（2-5 个）。用户提出两个关键直觉：(1) journal 按账号拆分（每人一个 id.ndjson）；(2) 域名侧只需 `/.well-known/did.json` + TXT 指向本 PDS，PDS 假设用户把 service 指向自己。

> **已更正（2026-08-16，见 ADR-039）**：本 ADR 中"handle 解析必须 DNS TXT"、"account add 写入 public/accounts.json 注册表"、"主账号公钥依赖环境变量"等论断已被后续调研推翻/演进 —— handle 解析有 HTTP well-known 回退（无需 DNS），注册表与 OWNER_PUBLIC_KEY 环境变量已被"journal 派生 did + well-known 自发现公钥"完全取代。统一 journal + per-did 链 + did:web 用户域名身份的核心决定不变。

协议约束调查（本地 indigo 源码确认）：

- **relay 拒绝路径式 did:web**（`did.go:81-83` 对 identifier 做 ParseHandle）→ 每账号必须是**独立简单主机名的 did:web**（如 `pub1.example.com`）；
- **handle 解析走 DNS TXT**（`handle.go:32-44` 查 `_atproto.<handle>`，值 `did=did:web:...`）→ 账号域名必须是持有者可加 TXT 的域名（workers.dev 不行）；
- **firehose seq 必须流内严格递增**（`consumer.go` per-connection）→ offset-as-seq 只在**单一文件**下天然成立；
- did.json 必需内容：verificationMethod（账号公钥）+ atproto_pds service（endpoint = 本 PDS URL）—— 与主账号同结构。

## Decision

**统一 journal.ndjson**（所有账号事件按时间追加，每行带 did；offset = 全局 firehose seq，**保留 offset 推断 seq 的设计**）。"每人一个 id.ndjson"会破坏 offset 全局单调（各自从 0 起，同流碰撞被 relay 静默丢弃）—— 单文件 + per-did 过滤视图是两全解。

- **身份在用户域名**：每账号 `did:web:<子域>`，账号持有者在其域名粘贴 did.json（公钥 + service=本 PDS）并加 `_atproto` TXT；PDS 不托管身份文档，只托管 repo。
- **CLI**：`account add <handle>`（生成密钥对 + 输出 did.json/TXT 粘贴内容 + 注册表 `public/accounts.json`）；`post --account <id>` 用该账号密钥签名，per-did 取 prev 追加到统一 journal。
- **Worker**：journal 校验与索引**按 did 分组**（每账号独立 commit 链）；XRPC 按 hosted did 路由（getRepo/getRecord/getBlob 等，blobs 在 `uploads/<accountId>/`）；firehose 透传所有托管账号事件。
- **主账号向后兼容**：现有 did:web 主账号即"hosted 集合"的一员，数据零迁移（行已带 did）。
- 签名校验按账号公钥（config.accounts.json，gitignored，私钥仅在本地）。

## Consequences

优点：

- offset-as-seq 设计保留，零新机制；统一 journal 与现有格式/数据兼容；
- 多账号联邦一次 requestCrawl 覆盖（relay 按 host 订阅，`EnsureAccountHost` 校验 did 的 PDS == 本 worker）；
- 身份完全在用户侧（域名 + TXT），PDS 无 did:plc 依赖、无 PLC 目录外部依赖；
- 每账号独立密钥，互不关联。

缺点：

- **handle 解析依赖账号持有者配置 DNS**（TXT 是硬前提，无 TXT 则 handle 不可解析，账号只能以 DID 存在）；
- 统一 journal 中多账号事件交错，per-did 链语义比单账号复杂（校验/写入两侧都需按 did 分组）；
- 单 Worker 共享一份免费配额（DO/请求），多账号叠加在同一预算内；
- 每账号一次部署周期（账户 add 后 journal 更新需部署才生效，与发帖同频）。
