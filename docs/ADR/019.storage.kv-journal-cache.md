## Context

Worker 每次 HTTP 请求都需要加载 journal 内容。Journal 内容有三个可能的来源：

1. **KV 缓存**（`JOURNAL_KV`）— Cloudflare Workers KV
2. **环境变量**（`JOURNAL_CONTENT`）— 部署时写死在 `wrangler.toml` 的 `[vars]` 中
3. **HTTP 远程拉取**（`/refresh` 端点）— 从 `JOURNAL_URL` 获取

环境变量方案的限制：

- Workers 环境变量单个值上限约 1KB（vars 总上限约 32KB），journal 增长后放不下
- 环境变量是部署时静态的，无法在运行时更新
- `dev:local` 脚本通过 `--var JOURNAL_CONTENT:"$(cat journal.ndjson)"` 注入，仅适合本地开发

如果没有 KV，`/refresh` 从远程拉取的 journal 内容无处可存，下一次请求又回到环境变量中的旧数据。

## Decision

使用 Cloudflare Workers KV 作为 journal 的运行时缓存。

加载优先级：

1. `JOURNAL_KV.get('journal')` — KV 缓存（优先）
2. `env.JOURNAL_CONTENT` — 环境变量 fallback（本地开发）

`/refresh` 端点拉取新 journal 后：

1. 校验 journal 链完整性（CID + prev）
2. 更新内存中的 events
3. 写入 `JOURNAL_KV.put('journal', content)` 持久化缓存

KV 的一致性模型（eventual consistency）是可接受的：

- Journal 是 append-only 的，最终一致性只意味着部分请求可能短暂看到旧版本
- Cron 每 5 分钟也会触发 refresh，KV 会很快收敛

## Consequences

优点：

- Refresh 后 journal 立即持久化，不依赖环境变量
- 支持任意大小的 journal（KV 单个值上限 25MB）
- 跨请求共享缓存，每个请求不需要重新拉 HTTP

缺点：

- 需要额外的 Cloudflare KV 配置（`wrangler kv namespace create`）
- KV 是 eventual consistency，极端情况下可能读到旧数据
- 增加了一个外部依赖

## 替代方案

如果不需要 `/refresh` 功能（journal 只通过环境变量提供），可以不用 KV。但环境变量有大小限制，不适合生产使用。
