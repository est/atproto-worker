## Context

给"文本只读广播"PDS 加图片/附件能力。用户否决了远程模式（BLOB_BASE_URL），确定：**blob 与 journal.ndjson 同级存放（public/uploads/），都随 Worker 静态资产部署**。

协议事实（本地 atproto-reference 确认）：

- 图片以 `app.bsky.embed.images` 嵌入帖子，每张 `{image: {$type:'blob', ref:{$link:cid}, mimeType, size}, alt, aspectRatio}`，最多 4 张、单张 ≤1MB；
- **blob CID 是 raw codec（0x55）**，前缀 `bafkrei...` —— 不是 dag-cbor（0x71）的 `bafyrei...`，现有 `computeCID` 不能用于 blob；
- relay/appview 通过 `com.atproto.sync.getBlob?did&cid` 取图（PDS 实现、无鉴权、`encoding: */*`）；图片要显示，getBlob 必须工作；
- firehose #commit 的 `blobs` 数组需列出记录引用的 blob（relay 校验 blob 声明）。

## Decision

- **存储**：`public/uploads/<cid>.<ext>`（扩展名带 mime 信息，用户选择，不用 manifest）；getBlob 用固定候选扩展名列表（jpg/jpeg/png/gif/webp/avif）经 ASSETS binding 探测，命中即得 mime，响应带 `Cache-Control: public` 边缘缓存。
- **CID**：`src/shared.js` 新增 `computeBlobCid`（CIDv1 + raw 0x55 + sha2-256，与 dag-cbor 的 `computeCID` 分离）+ `isValidCidString`（getBlob 输入校验）。
- **firehose**：`formatEvent` 递归 walk 记录提取 `{$type:'blob', ref:{$link}}` → 填入 commit 的 `blobs` 数组。
- **CLI**：`seal.js post "文本" --image a.jpg [--image b.jpg] [--alt "描述"]` —— 构建 embed（aspectRatio 用 `image-size`，0 依赖，取图片宽高），blob 文件复制到 `public/uploads/`。
- **无远程模式**：BLOB_BASE_URL 不引入；单一数据源=随包资产，与 journal 一致。

**过程发现并修复的关联 bug（重要）**：ADR-034 移除身份变量后，Firehose DO 里 `env.OWNER_DID` 为 undefined —— DO 无请求 host 可派生，`broadcast()`/`backfill()` 按 `did === undefined` 过滤，**静默丢弃全部事件**：游标永不推进、relay 收不到新帖（表象：/refresh 反复报相同条数）。修复：worker 在广播负载里显式传派生 ownerDid，backfill 从 journal 自身事件派生，两者在 owner 未知时 fail-open（journal 天然只含 owner 事件）。回归测试覆盖。

## Consequences

优点：

- 与静态哲学一致：git 即备份、零外部依赖、CDN 边缘缓存、发布=部署；
- 图片在 bsky.app 完整可见（实测：postsCount 5、embed view 带 alt/aspectRatio、getBlob 字节一致）；
- 零新增运行时依赖（image-size 仅 CLI devDependency，0 依赖树）。

缺点：

- 每张图一次部署（与发帖同频，静态模型固有）；
- getBlob 首次访问最多 ~6 次 ASSETS 探测（404），成功后被边缘缓存兜住；
- 二进制进 git，仓库随图片增长（个人规模可接受）；
- 无上传端点（uploadBlob 属写路径 ADR-035，本 ADR 不含）。
